## 1. 原工程审计结论（设计约束的事实基础）

### 1.1 页面与代码结构

| 项 | 现状 |
|---|---|
| 工程 | `B_QINGYU/`，PlatformIO + Arduino + LovyanGFX + LVGL 8.3.11 |
| 逻辑分辨率 | 320×240 横屏；物理面板 240×320，`setRotation(1)`，**已由用户目视确认方向正确** |
| 页面 | 6 个：BOOT / HOME / TASKS / MEMOS / REMINDERS / GUEST |
| UI 实现 | `src/ui/qingyu_ui.cpp`（C++ 移植版）、`src/ui/ui_theme.cpp`、`src/ui/ui_bridge.cpp` |
| 色系 | 奶油米黄 `#F7F4EC` / `#EEE8DC` / 橙 `#E9A86D` / 墨绿 `#353A36` |
| 导航 | 无触摸；串口 `PAGE=`、`NEXT`、`PRIVACY=`；命令缓冲 63 B |
| 隐私 | 上电 BOOT → GUEST；私有 setter 在 Guest/BOOT 直接丢弃文本；`PRIVACY=OWNER` 仅本地调试 |
| 状态与采样 | `Snapshot` 单结构体 + mutex，UI 每 1 s tick 读快照 |
| 动态中文 | 288 码点白名单 `sunisle_cn_chars.h`，超集汉字由 `sanitizeDynamic()` 降级为 `?`；Bridge 栅格化通道留 TODO |

**与 UI 2.0 的差距**：页面数 6 → 4（2 个工作页 + BOOT + GUEST）；色系整体更换；字重/字号层级单一；TASKS / MEMOS / REMINDERS 三页需删除并合并；任务进度、已完成任务数、AI 摘要、下一项任务需全部整合进首页。

### 1.2 字体资源、符号覆盖与实际占用（要求先检查，已检查）

字库由 `B_QINGYU/tools/gen_cn_font.py` 从本机 Windows 字体离线栅格化，**8bpp alpha，未引入完整中文字库**。

| 字库面 | 字号 | 字形数 | 位图字节 | 来源字体 | 用途 |
|---|---:|---:|---:|---|---|
| `sunisle_cn_14` | 14 | 288 | 56,448 | 微软雅黑 | 正文、日期、数量、引文 |
| `sunisle_cn_16` | 16 | 288 | 73,728 | 微软雅黑 | 标题、主文案、列表行 |
| `sunisle_cn_28` | 28 | 2 | 1,568 | 楷体 | 「晴屿」品牌字 |
| `sunisle_cn_boot` | 16 | 12 | 3,072 | 楷体 | 开机标语 |
| `sunisle_cn_kai_16` | 16 | 54 | 13,824 | 楷体 | 栏目标题、问候语、竖排标签 |
| **CJK 合计** | | | **148,640 B** | | 生成文件 `src/ui/sunisle_cn.cpp` 968,650 B（C 数组文本，非链接体积） |
| LVGL 内置 Montserrat | 12/14/16/18/28 | Latin | 已启用 | — | ASCII / 数字 / 字标 |

- ASCII 与数字走 `lv_font_t.fallback` → Montserrat，中文不缺字的前提是**该汉字在白名单内**。
- 白名单 `kSunisleCnCount = 288`，覆盖 UI 1.0 全部静态文案 + 30 条每日一言 + 天气词汇。
- **UI 2.0 静态文案缺字审计**：新文案共需 85 个汉字/中文标点，其中 74 个已在白名单，**缺 11 个**：`伴 侣 动 后 启 完 情 桌 确 详 面`。并入 14/16 两档 8bpp 成本 = 11 × (14² + 16²) = **4,972 B**；若楷体标题面也要用，另加 11 × 256 = 2,816 B。
- 中文标点已包含在楷体面，不需 fallback 到 Montserrat。
- **4bpp 字库禁用**：上游 `1ab7ea3` 的 4bpp 重打包在真机出现缺字，`verify_fonts.py` 自检通过也不能证明真机可用。UI 2.0 继续 8bpp。

### 1.3 容量账（app0 = 1,310,720 B）

| 固件 | 字节 | app0 占比 | 余量 |
|---|---:|---:|---:|
| `build_e` 阶段 C 首版 | 1,164,928 | 88.88% | 145,792 B |
| `build_f` 字号/品牌修订 | 1,242,400 | 94.79% | 68,320 B |
| **`build_g` 当前设备运行版** | **1,294,768** | **98.78%** | **15,952 B** |

**结论：当前余量 15,952 B，放不下 UI 2.0 的新数字字体与交互层。** 实施前必须先瘦身，见 §9.4。

### 1.4 不可回避的硬件门禁

1. **触摸当前不可用。** 白屏二分已确认：`e3f5cb2` 的 XPT2046 共享 HSPI + LVGL pointer indev 轮询 + 全屏 `touch_catcher` 是 `1ab7ea3` 真机白屏的根因；`TOUCH_CS=33` 未经按压实测，CS/校准/可用性一律「未确认」。当前 `main.cpp` 中 `touch::begin()` 被有意挂起、未注册 indev。
   → 本规范**完整定义**滑动/轻触/长按的目标交互（§8），但实施落地时页面切换与动作先走串口/Bridge 等价映射；触摸坐标通道保留接口，未经引脚与总线隔离验证**不得启用 indev**。此项需用户单独决策。
2. **不得改动 GPIO、屏幕旋转、SPI 参数**：`setRotation(1)`、20 MHz HSPI、`LCD_PIXEL_SWAP=true` 均已目视验证，属冻结参数。
3. **RGB565 色差**：面板 16 bit，设计稿 sRGB 会量化。已算得实际回读值（见 §3），白色会偏 `#F8FCF8`，设计规范以 sRGB 为准，真机验收允许 ±8/通道偏差。
4. **USB 串口**：115200，命令缓冲 63 B；UI 2.0 不增加大包，Bridge 长文本走后续 JSONL/栅格化通道。

## 2. 产品视觉定位

**Intelligent Desk Companion** — 现代消费级科技桌面终端，不是电子相框、不是日历、不是仪表盘。

关键词：Premium / Minimal / Modern / Intelligent / Editorial / Calm。

设计手法：**靠版式、字号层级、留白与一处品牌色建立秩序**，不靠渐变、阴影、图案、Emoji、大圆角。整屏彩色面积控制在 8% 以内。

### 3.3 使用规则

- 品牌蓝只用于**重点数字、选中状态、重要操作、状态标识**；科技青只用于在线状态；绿只用于完成；橙只用于提醒。
- 不允许每页换色系；不允许大面积渐变；不允许彩色块铺底。
- 页面背景一律 `BG`，卡片 `SURFACE`，卡片**无阴影、无边框**，靠底色差与留白分层。
- 单页最多 2 个卡片（首页 1 个计数卡；备忘页 2 个内容卡），摘要/下一项任务用**无卡区块 + 分割线**。

## 4. 字体 Token

### 4.1 层级定义

| Token | 字号 | 字重 / 字形 | 字体资源 | 颜色 | 用途 |
|---|---:|---|---|---|---|
| `NUM_XL` | 34 px | 现代无衬线 Light | **新增** `sunisle_num_34`（仅 `0-9 : - / .`） | `INK` | 首页时间、访客时间 |
| `NUM_L` | 24 px | 无衬线 Medium | 新增数字面 24 px 或 `NUM_XL` 缩放 | `BRAND` | 今日任务数、进度分子 |
| `TITLE` | 18 px | 中文中等 | `sunisle_cn_16` 16 px 承载 / 或新增 18 px | `INK` | 页面标题「备忘与提醒」 |
| `HEADING` | 16 px | 楷体（对比面） | `sunisle_cn_kai_16` | `INK` | 欢迎语、栏目标题 |
| `BODY` | 14 px | 中文常规 | `sunisle_cn_14` | `INK` | 摘要、列表标题、日期 |
| `CAPTION` | 10 px | Latin 小字 / 中文 14 px 降级 | Montserrat 10 / `sunisle_cn_14` | `MUTED` | 分区标签、状态、更新时间 |
| `BRAND_CN` | 28 px | 楷体 | `sunisle_cn_28` | `INK` / `GUEST_INK` | 「晴屿」品牌 |
| `BRAND_EN` | 10 px | 字距 3–8 | Montserrat 10 / 12 | `MUTED` / `TECH` | `SUNISLE` / `QINGYU` 字标 |

- 数字与中文混排：数字用独立数字面，中文用 14/16 px 子集，底部基线由 LVGL label 对齐，不做手工偏移。
- 层级靠**字号 + 字色 + 字重对比**，不靠全部加粗；同屏至少 4 级字号。
- 中文标点必须与文字同字库（楷体面已含 `，。、！？；：（）`）。
- **设计稿按目标字号绘制**（`TITLE` 18 px、`NUM_XL` 34 px）。落地时若新增 18 px 中文面，需按实际标题用字另建小字集（每字 18²=324 B）；优先方案是复用现有 `sunisle_cn_16`，视觉差 2 px 可接受，可省一个字库面。此选择列入 §11 待确认。
- `CAPTION` 中的中文必须用中文字库面绘制，`LINE` 色描边在浅底上过淡，次按钮描边统一改 `MUTED`。

### 4.2 新增字体资源与体积

| 新增项 | 规格 | 预计链接体积 |
|---|---|---:|
| `sunisle_num_34` | 8bpp，14 字形（`0-9 : - / .`），Segoe UI Light 栅格化，34×34 方框 | 16,184 B |
| UI 2.0 缺 11 字并入 `sunisle_cn_14` / `_16` | 8bpp | 4,972 B |
| 楷体标题面按需扩 11 字 | 8bpp 16 px | 2,816 B |
| **合计新增** | | **≈ 23,972 B** |

替换现有 `LV_FONT_MONTSERRAT_28`（约 25 KB）后**净增约 0 B**；再叠加删三页省下的 8–15 KB，UI 2.0 理论可放进当前余量，但**余量仍过窄**，必须先执行 §9.4 瘦身。

### 4.3 中文缺字防护

- 静态文案：§1.2 的 11 个缺字必须并入生成器 `SPECS` 并重新生成字库。
- 动态文案（AI 摘要、任务标题、备忘内容、提醒事项）：任意汉字子集永远无法覆盖。保留现有 `sanitizeDynamic()` 白名单降级；阶段 D 的 Bridge 侧**栅格化位图下发**是正式解法（`qy_ui_set_dynamic_bitmap()` 接口已在 `qingyu_ui.h` 预留 TODO）。
- 验收项：真机逐页目视，出现豆腐块 / `?` 即判不通过。

## 5. 页面结构与信息架构

```
上电
 └─ BOOT（1.5 s，启动专用）
     └─ GUEST（默认，覆盖式隐私状态，强制）
         └─ [Bridge 授权验证通过] → OWNER
              ├─ HOME      工作首页   （主页面 01）
              └─ MEMOS     备忘与提醒 （主页面 02）
                 └─ [锁屏 / 离开 / 撤销授权] → GUEST（清空私有文本）
```

**正常工作状态只有 2 个可导航页面**：HOME 与 MEMOS。BOOT 是临时启动画面，GUEST 不是导航页而是隐私覆盖层，不进入轮播、不显示页码。

| 画面 | 必需内容 | 禁止内容 |
|---|---|---|
| HOME | 时间、日期星期、今日任务总数、已完成数、AI 摘要（≤2 行）、下一项重要任务、连接状态 | 独立任务列表、卡片堆叠、装饰图案 |
| MEMOS | 上：最重要一条提醒（时间/标题/状态/确认·稍后）；下：最近一条 AI 备忘（标题/摘要/更新时间/详情） | 第三条及以上的多页导航 |
| BOOT | 晴屿品牌、产品名称、`AI 桌面工作伴侣`、启动状态 | 复杂动画、长停留 |
| GUEST | 品牌、欢迎来访、主人暂时离开工位请稍候、日期时间、公开每日一言 | 任何私人任务/备忘/摘要/财务/通知历史；触摸返回 Owner |

## 7. 组件与图标规范

- **卡片**：`SURFACE`、圆角 **8 px**、无边框、无阴影、无内边距堆叠；单页 ≤ 2 个。
- **分割线**：1 px `LINE`，左右缩进到安全边距内。
- **状态点**：r=3 实心圆，`TECH` 在线 / `ALERT` 待处理 / `LINE` 离线。
- **进度条**：4 px 高，`LINE` 轨 + `SUCCESS`（完成）/ `BRAND`（启动）填充，直角。

- **品牌锁**：「晴屿」用楷体品牌面，`SUNISLE` 用 Montserrat + 字距，两者组合不拆散、不改色系。
- **留白**：区块之间 ≥ 8 px；文字行高 ≥ 字号 + 2 px；任何两块内容不共用同一基线堆叠。

## 9. 性能与 LVGL 实施约束

1. LVGL 8.3.11；保持 LovyanGFX 驱动与原触摸驱动文件；不改 GPIO / 旋转 / SPI 参数。
2. 不引入第三方库；不使用大尺寸双缓冲，沿用 `LVGL_BUF_LINES = 12`（320×12 部分缓冲）。
3. **对象数量**：每页常驻 LVGL 对象 ≤ 30（当前六页合计更多，合并页后下降）；条目对象预创建复用，禁止运行时反复 `lv_obj_create` / 删除。
4. **无复杂动画**：仅 BOOT 进度条一次线性推进与页面切换淡入（≤200 ms）；禁止并行动画、禁止全屏渐变。
5. **减少全屏刷新**：只有时间数字、状态点、进度条按 tick 更新；静态文本用 `lv_label_set_text_static` 或值未变则不 set。
6. 避免频繁动态内存分配：Bridge 字符串用固定长度缓冲 + `sanitizeDynamic()` 原地处理，不缓存长文本副本。
7. **背光策略**：闲置 60 s 降至 `BL_DEFAULT` 的 40%；触摸/提醒/Bridge 事件恢复 100%；仅 GUEST 可长期低亮度。
8. 常亮稳定：72 h 压测、Guest/Owner 切换 100 次无私有文本残留。
9. **容量与瘦身（实施前必做）**：
   - 当前余量 15,952 B，删三页预计省 8–15 KB，仍不足以安全容纳阶段 D 的 Bridge/JSONL。
   - 优先：把 `sunisle_cn_16` 从 288 字缩到 16 px 实际用到的静态字集（预计省 **30–40 KB**），白名单继续取自 14 px 不受影响。
   - 次选：自制 14 字形数字子集替换 `LV_FONT_MONTSERRAT_28`（净省约 9 KB）。
   - 不推荐扩分区表（会动 bootloader/分区，风险高）。
10. 每步改动单独编译、单独烧录、单独抓日志；**目视结论只能由人眼给出**，串口 flush / heap / STATE 一律不能代替看屏。
